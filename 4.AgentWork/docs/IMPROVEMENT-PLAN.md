### v2.3 远期（2027-05+）— WordPress 式产品周边 + 用户生态 🔮

**用户原话 1**："也要能在模版基础上去灵活修改的机制，就像 **wordpress** 那样灵活的前端模版+各种功能插件和应用模块，还有丰富强大的在线服务"

**用户原话 2**："**最终能打造产品周边+用户生态**"

**核心洞察**：
> WordPress 之所以能统治互联网 20+ 年，不是因为 WordPress 本身多强，
> 而是因为它打造了"**核心 + 主题 + 插件 + 应用市场 + 在线服务**"的可扩展生态。
> AgentWork 的终极目标就是成为 **"AI 智能体领域的 WordPress"**。

| **插件（Plugin）** | 员工能力插件 | 邮件 / CRM / 支付 / OCR / 知识库 |
| **应用市场** | 模板 + 插件市场 | 30+ 模板 + 100+ 插件 |
| **在线服务** | 云集云服务 | LLM Gateway / 同步 / 备份 / 监控 |
| **用户生态** | 创作者 + 开发者 | 收入分成 + 培训认证 + 合作伙伴 |

**5 层生态体系**：

#### 第 1 层：核心（Core）— AgentWork 内核
- **员工定义引擎**（YAML + 验证）
- **培训引擎**（RAG + 规则 + 话术 + 评估）
- **任务调度引擎**（DAG + 重试 + 状态机）
- **插件加载器**（动态加载 + 沙箱隔离）
- **主题渲染器**（UI 主题切换）
- **API 网关**（内部 + 外部）

#### 第 2 层：产品周边（Product Periphery）— 对外能力
- **REST API**：外部系统调用 AgentWork 员工
  ```
  POST /api/v1/employees/{id}/chat
  POST /api/v1/templates/{id}/install
  GET  /api/v1/employees/{id}/status
  ```
- **Webhook**：事件订阅（员工回复 / 任务完成 / 错误）
  ```
  on_message_received
  on_task_completed
  on_employee_error
  ```
- **CLI**：`yunji employee chat fashion_stylist --message "推荐搭配"`
- **SDK**（Python / Node.js / Go）：让开发者集成到自己的应用
  ```python
  from yunji import AgentWork
  client = AgentWork(api_key="...")
  result = client.employee("fashion_stylist").chat("我身高 165, 微胖")
  ```
- **嵌入式**：把 AI 员工嵌入 Web / 桌面 / 移动（iframe / SDK / 小程序）

#### 第 3 层：开发者生态（Developer Ecosystem）— 插件 + 集成
- **插件 SDK**（Rust trait + Python/Node 绑定）
  ```rust
  pub trait Plugin {
      fn name(&self) -> &str;
      fn version(&self) -> &str;
      fn execute(&self, ctx: &PluginContext) -> Result<PluginOutput>;
  }
  ```
- **内置插件**（10+ 起步）：
  - 邮件插件（SMTP / IMAP / 模板）
  - CRM 插件（Salesforce / 飞书 / 销售易 / 钉钉）
  - 支付插件（支付宝 / 微信 / Stripe / PayPal）
  - 数据分析插件（SQL / Pandas / 图表）
  - OCR 插件（百度 / 腾讯 / 阿里 OCR）
  - 知识库插件（Notion / 飞书文档 / 语雀）
  - IM 插件（飞书机器人 / 钉钉机器人 / 微信客服）
  - 工单插件（Jira / 禅道 / 自研）
  - 日历插件（Google Calendar / 飞书日历）
  - 语音插件（ASR / TTS）
- **插件市场**（公开 + 付费，30% 分成）
- **开发者文档 + 示例 + 认证**
- **开发者大会**（线上 + 线下）

#### 第 4 层：创作者生态（Creator Ecosystem）— 模板 + 主题
- **模板市场**（5 核心 + 5 候补 + 30+ 社区）
- **主题市场**（10+ 行业 UI 主题）
- **创作者后台**（模板编辑 / 提交 / 收入 / 数据）
- **创作者认证**（Lv1 入门 / Lv2 资深 / Lv3 大师）
- **30% 收入分成**（公开模板收费，平台抽 30%）
- **创作者大会 + 比赛**

#### 第 5 层：合作伙伴生态（Partner Ecosystem）— SI + 咨询 + 培训
- **系统集成商**（SI）：帮客户落地
- **咨询商**：帮客户梳理 AI 员工定义
- **培训机构**：AgentWork 认证工程师 / 培训师
- **行业合作伙伴**：行业协会 / 联盟
- **分成模式**：实施费 30-50% 分给 SI

#### 第 6 层：客户生态（Customer Ecosystem）— 社区 + 案例
- **用户社区**（论坛 / 微信群 / Discord）
- **案例库**（5 行业 × 10 客户 = 50 案例）
- **最佳实践库**（10+ 行业 SOP）
- **客户成功团队**（CSM）
- **客户反馈通道**（需求直达产品）

## 4. 关键决策记录（ADR）

### ADR-001：品牌名保持 AgentWork

**决定**：不更名为 AI-Work / AgentEmployee。

**理由**：
- 仓库/域名/CLI/crate/npm 已全部押注
- "Agent" 在 AI 业内是通用词
- 子品牌留到 GA 之后

**影响**：定位叙事要中性化，README 不再强调"代码"。

### ADR-002：定位升级为"AI 智能体工作台"

**决定**：从"AI 研发团队协作"扩为"AI 智能体工作台"。

**理由**：
- 一个公司能用的 AI 智能体可能远多于"团队协作"场景
- 多数岗位是"独立工作"的，不是"协作"的
- 跨行业（医疗/法律/教育/电商）需要中性定位

### ADR-003：互动机制与任务驱动共存

**决定**：ChatPanel + TaskBoard 双入口，不二选一。

**理由**：
- 维护阶段离不开互动（修 bug/调参数）
- 开发阶段任务驱动更高效
- 两者可互转

### ADR-004：培训系统作为核心壁垒（但纯 prompt）

**决定**：把"AI 员工培训"作为核心壁垒，但**只用 prompt + few-shot**，不做 LoRA 微调。

**理由**：
- 团队协作框架（CrewAI/AutoGen）已成熟
- 培训数据飞轮是独家壁垒
- LoRA 微调需要 GPU，宝塔 4核8G 跑不动
- prompt 工程的 6/10 准确率已经够用，剩余 4 分靠数据量堆

### ADR-005：本地优先 + 云端协同

**决定**：本地为主，云端（宝塔）做反代 + 备份 + 同步。

**理由**：
- 用户隐私数据不出本地
- 4 核 8G 服务器跑不动高负载
- 渐进投入：等收入稳定再升配

**不做的**：
- ❌ 云端 LLM 训练
- ❌ 云端 Agent 运行时（OpenHands Cloud 模式）
- ❌ 多租户 SaaS
- ❌ GPU 推理

### ADR-006：千问/智谱 API 归类为"云集 LLM Gateway"（v2.0 调整）

**决定**：qwen2api / zhipu2api 升级为"云集 LLM Gateway"。

**理由**：
- 1.PC 散落的反代代码可复用
- AgentWork 通过 Gateway 统一调用 LLM
- 新增收入来源（按 token 抽成）

**v2.0 调整**：
- 先复制，不重构（M4.0 D7）
- 部署在宝塔，5G 内存足够
- **不**做负载均衡 / 高可用（单实例够用）

### ADR-007：行业模板聚焦 5 个核心 + 社区机制（v2.1 调整）

**决定**：M4.2 做 **5 个核心行业模板 + 社区模板机制**（电商客服 + 教育助教 + 销售跟进 + 法律咨询 + 财务对账）。

**理由**：
- v1.0 写 5 个太赶，质量难保证
- v2.0 砍到 2 个太少，B 端获客困难
- v2.1 折中：5 个核心保证质量 + 社区机制扩展数量
- B 端采购决策：行业方案存在性 = 通过/否决
- 5 个行业覆盖 60-70% 商业市场（客服/教育/销售/法律/财务）
- 社区机制让模板数 6 个月后从 5 → 30+

**5 个核心模板**：
1. **电商客服**（最简单，1 周）— 50 万+ 中小企业
2. **教育助教**（K12，1 周）— 30 万+ 培训机构
3. **销售跟进**（B2B，1 周）— 100 万+ 销售型企业
4. **法律咨询助理**（严格规则，1 周）— 5 万+ 律所
5. **财务对账**（OCR + 对账，1 周）— 200 万+ 中小企业

**每个模板 = 3 个员工**（售前/中/后 或 3 个独立岗位）：
- 5 模板 × 3 员工 = **15 个内置员工**

**社区模板机制**（杠杆倍增器）：
- 模板市场 UI（Marketplace.tsx）
- 模板提交向导 + 自动校验
- 自动 LLM 评估 + 人工审核
- 公开模板免费，付费模板 30% 分成
- 6 个月后社区作者自发上传 = 30+ 行业模板

**B 端覆盖**：
- 单做 5 个 = 5 行业
- 加社区机制 = 5 + 2-5 社区 = 7-10 行业
- 1 年后 = 30+ 行业
- **网络效应启动后，每年模板数 10x 增长**

|------|------|------|
| **LoRA 微调** | 有 GPU 资源后 | 4 核 8G 跑不动 |
| **跨岗位实时协作** | M5+ | 云端长连接耗资源 |
| **企业私有化部署** | GA 后 | 需要专业运维 |
| **自定义私有 LLM** | GA 后 | 需要 GPU |
| **SLA 99.9%** | GA 后 | 单实例做不到 |

### 6.3 砍掉原 ROADMAP 的事

| 原计划 | 砍掉原因 |
|--------|---------|

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|------|:---:|------|
| 范围蔓延（M4.0 拖到 M4.1+）| 🟡 中 | 严格 deadline，超出进 backlog |
| 培训系统复杂度超预期 | 🟡 中 | MVP 先用 hnsw_rs，迭代优化 |
| 宝塔服务器 OOM | 🟡 中 | 单实例 + 限流 + 监控 |
| 宝塔磁盘 < 30G 不够 | 🟡 中 | 监控 80% 报警，syncthing 定期清理 |
| ChatPanel 与 TaskBoard 冲突 | 🟢 低 | 明确分工：Chat = 互动，TaskBoard = 执行 |
| 行业模板质量参差 | 🟡 中 | 内置模板要可定制，不要硬编码 |
| 5 模板 1 周/个 时间太紧 | 🟡 中 | 每个模板 1 周 = 12 工作日，足够基础内容；2-3 周内迭代 |
| 社区模板作者投稿少 | 🟡 中 | 先 5 个核心 + 30% 分成 + 营销推广 |
| 社区模板质量低 | 🟡 中 | 自动 LLM 评估 + 人工审核双层 |
| 启动.bat 闪退 | ✅ 已修 | 纯 ASCII + 0 子 shell 解析 |
| 客户培训数据敏感 | 🟡 中 | 加密传输 + 客户端删除按钮 |
| **5 细分模板业务流过深**（v2.2 新增）| 🟡 中 | 自定义向导（D6）让客户适配自己的流程，不必硬套 |
| **模板自定义向导 1 周做不完**（v2.2 新增）| 🟡 中 | MVP 先做 fork 机制 + 可视化编辑，AI 自动生成放到 v2.3 |
| **5 候补模板延期到 Beta 后**（v2.2 新增）| 🟢 低 | 自定义向导让客户先自助造模板，反馈后我们再做候补 |
