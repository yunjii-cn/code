# work.yunjii.cn 与 aw.yunjii.cn 双站点开发计划

> 状态：Phase 1 完成，移交线上部署  
> 范围：官网站点 / 产品矩阵 / AgentWork 转化  
> 最近更新：2026-06-27

## 1. 总体结论

先在当前仓库孵化两个独立站点：

- `work.yunjii.cn/`
- `aw.yunjii.cn/`

不要先拆两个远程仓库。当前阶段的重点是统一文档、定位、视觉和转化路径。两个站点目录、构建命令、部署配置从第一天保持独立，等上线稳定且发布节奏分化后再拆仓。

## 2. 站点定位

### 2.1 work.yunjii.cn

定位：云集工作台矩阵门户。

职责：

- 解释云集 4 代产品矩阵
- 帮用户选择 Free / Pro / Business / Enterprise
- 承接统一登录、SSO 和应用启动器
- 作为云集生态路由中枢
- 后续接入 UM 统一用户数字身份管理系统

不做：

- 不承载具体产品重业务
- 不做另一个 BizWork
- 不直接运行 Agent 或编辑项目
- 不自建独立用户表，用户身份由 UM 管理

### 2.2 aw.yunjii.cn

定位：AgentWork 旗舰产品站。

职责：

- 讲清 AgentWork 的独立价值
- 主推 AI 员工、AI 团队、行业模板、自进化工作台
- 承接企业咨询、预约演示、早期试用
- 展示行业模板和核心能力
- 引导登录或试用时跳转/接入 `work.yunjii.cn` 统一身份

不做：

- 不自建独立登录体系
- 不维护独立用户数据库
- 不把前 3 代产品作为同等重点展示

## 3. 信息架构

### 3.1 work.yunjii.cn 首页

建议模块：

1. 顶部导航：产品、价格、下载、文档、登录
2. 首屏：云集智能工作台，4 类用户一站选择
3. 产品矩阵：云集 PC 版 / 云集 Web 版 / 云集团队版 / AgentWork
4. 选择向导：个人、本地隐私、轻量多端、团队协作、行业 AI 员工
5. 价格对比：Free / Pro / Business / Enterprise
6. 统一账号说明：一次登录，全端通行
7. 下载与入口：各产品启动、下载、申请试用
8. 页脚：公司、备案、隐私、服务条款

### 3.2 aw.yunjii.cn 首页

建议模块：

1. 顶部导航：产品、行业模板、能力、路线图、预约演示
2. 首屏：AgentWork / 云集智能体工作台
3. 核心叙事：不是 AI 编程工具，而是 AI 智能体工作台
4. 五大支柱：AI 团队、AI 员工培训、行业模板、互动双引擎、本地优先 + 云端协同
5. 行业模板：电商、教育、金融，后续扩展法律、财务、HR、医疗
6. 工作流演示：从任务到 DAG，到员工协作，到验证交付
7. 企业价值：可控、可审计、可私有化、可培训
8. 路线图：M0 到 Beta/GA
9. CTA：预约演示、申请早期试用、查看产品矩阵

## 4. 技术路线

首版建议：

- 前端：React + Vite + TypeScript
- 样式：Tailwind CSS 或轻量 CSS 变量
- 内容：静态 JSON / Markdown 抽取
- 部署：静态站优先，后续再接 BFF/API
- 表单：先用静态表单占位或轻量 API，避免一开始引入重后台

目录建议：

```text
work.yunjii.cn/
├── package.json
├── src/
├── public/
└── README.md

aw.yunjii.cn/
├── package.json
├── src/
├── public/
└── README.md

site-shared/          可选，后续再建
├── brand/
├── content/
└── tokens/
```

`site-shared/` 只放品牌色、Logo、产品矩阵 JSON、基础文案，不放业务逻辑。

## 5. 身份与登录

既然已有 UM 统一用户数字身份管理系统，并支持分组单点登录，推荐：

- `work.yunjii.cn` 作为统一身份入口和生态门户。
- `aw.yunjii.cn` 作为 UM 下的受管应用。
- AW 用户用 UM 主用户库，通过逻辑分组、租户、应用权限区分。
- AW 不配置独立用户数据库。
- 未登录访问 AW 的受保护入口时，跳转到 `work.yunjii.cn` 或 UM 登录流。

### 阶段 2：内容与转化

- 补价格页、FAQ、路线图、预约演示表单。
- 将 `doc/产品线矩阵.md` 和 `4.AgentWork/docs/` 中的能力提炼成站点文案。
- 建立基础 SEO 元信息。

### 阶段 3：线上灰度

- 两个域名分别部署。
- 配置 CDN、HTTPS、访问统计、表单投递。
- 验证移动端、桌面端、微信内置浏览器。

### 阶段 4：接入身份

- `work.yunjii.cn` 接 UM。
- AW 登录入口改为 UM/SSO 受管应用。
- 增加应用启动器、用户菜单、权限提示。

### 阶段 5：独立拆仓

满足以下条件再拆仓：

- 两站点发布节奏明显不同。
- 站点有独立 CI/CD。
- 站点内容和产品代码不再频繁互相调整。
- AW 官网开始承载独立销售线索、SEO 和企业转化。
