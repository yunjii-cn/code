## 架构演进

项目经历了两次架构演进：

| 版本 | 架构 | 桌面壳 | 体积 | 手机端 |
|------|------|--------|------|--------|
| v3.0 | PyQt6 + QWebEngineView | QWebEngineView (内嵌Chromium) | ~200MB+ | ❌ |
| v4.0 | FastAPI + Vue 3 + pywebview | pywebview (系统WebView2) | ~38MB | ✅ Capacitor |

### 为什么不用 PyQt6

- **体积过大**：QtWebEngine 内嵌 Chromium，EXE 200MB+
- **不支持 onefile**：QtWebEngine DLL 路径问题，必须 `--onedir` 模式（产生 `_internal/` 目录）
- **不支持手机端**：Qt 没有手机端打包方案
- **QWebChannel 是 Qt 专有协议**：无法复用到手机端

### 为什么选 pywebview + FastAPI

- **体积极小**：pywebview 调用系统 WebView2，不内嵌浏览器，EXE ~38MB
- **支持 onefile**：没有 DLL 路径问题，可以 `--onefile` 单文件打包
- **标准协议**：HTTP API + WebSocket，手机端直接复用前端代码
- **参考项目验证**：云集智能网联代理专家已成功采用此方案

### 过渡期策略

- 保留旧版 PyQt6 代码（`main.py` + `backend.py`），不删除
- 新版本通过 `api_main.py` 启动，独立开发
- 两个版本可并行运行，互不影响
- 新功能以旧版为参照物，用新技术依葫芦画瓢

## 自部署方案

### 设计目标

用户只需下载一个 **~15MB 的单EXE**，点击后自动完成：
1. 显示启动进度条
2. 检测/创建部署目录结构
3. 从 Gitee/GitHub 下载主程序 EXE
4. 创建桌面快捷方式
5. 启动主程序并删除自身

整个过程对用户来说就是"启动软件"的体验，自部署无感。

```

  云集智能编程工作站.exe  (launcher_stub, ~15MB, onefile)

  │  1. 检测部署目录是否已存在    │
  │  2. 已部署 → 直接启动主程序   │
  │  3. 未部署 → 显示进度条       │
  │     → 下载主程序单EXE        │
  │     → 创建文件夹结构          │
  │     → 创建桌面快捷方式        │

  └──────────────────────────────┘
         │
```

### 自删除机制（双重保障）

launcher_stub 启动主程序后需要删除自身，采用双重机制：

1. **优先 `--cleanup=`**：launcher_stub 传递 `--cleanup=<自身路径>` 给主程序，主程序 `launcher.py` 启动后主动删除该文件（最可靠，进程已退出文件肯定能删）
2. **兜底 `cmd /c del`**：同时启动一个后台 cmd 进程，延迟2秒后强制删除 launcher_stub（如果主程序不支持 `--cleanup=`，此机制兜底）

```python
# launcher_stub.py - _launch_app()
def _launch_app(exe_path, self_exe=None):
    args = [exe_path]
    if self_exe and os.path.isfile(self_exe):
        args.append(f"--cleanup={self_exe}")  # 机制1：主程序删除
    subprocess.Popen(args, ...)
    if self_exe and os.path.isfile(self_exe):
        # 机制2：cmd后台删除（兜底）
        bat = f'@echo off\nping 127.0.0.1 -n 3 >nul\ndel /f /q "{self_exe}"\n'
        subprocess.Popen(f'cmd /c ({bat})', shell=True, creationflags=0x08000000)
```

```python
# launcher.py - 启动时解析 --cleanup=
for arg in sys.argv[1:]:
    if arg.startswith("--cleanup="):
        _cleanup_path = arg[len("--cleanup="):]
if _cleanup_path and os.path.isfile(_cleanup_path):
    for _ in range(10):
        try:
            os.remove(_cleanup_path)
            break
        except PermissionError:
            time.sleep(0.5)
```

两种机制互不冲突：`--cleanup=` 先删掉了文件，`cmd /c del` 发现文件不存在就静默跳过。

### 部署目录检测

launcher_stub 通过以下逻辑确定部署目录：

1. EXE 同目录下有 `.yunji.lock` → 已是部署目录
2. EXE 同目录下有 `云集智能编程工作站/` 子目录且其中有内容 → 使用子目录
3. 以上都不满足 → 创建 `云集智能编程工作站/` 子目录作为部署目录

### 硬链接版本切换机制

版本切换采用硬链接映射（对齐参考项目"云集智能网联代理专家"）：

```
dev/
├── 云集智能编程工作站vXXX.exe     ← 硬链接入口（始终指向当前版本）
└── ver/
    ├── 云集智能编程工作站v2026.05.18.2348.exe
    └── 云集智能编程工作站v2026.05.18.1226.exe  ← 入口硬链接指向此文件
```

**工作原理**：
- `dev/` 下的 EXE 是 `ver/` 中某个版本 EXE 的硬链接
- 切换版本 = 删除旧硬链接 + 创建新硬链接（瞬间完成，无需复制大文件）
- 硬链接与原文件共享同一磁盘数据，不占额外空间

## 单实例控制机制

### 设计目标

确保同一台电脑上不会有同一 EXE 的多个实例同时运行，同时支持版本升级时平滑过渡。

### 技术实现

使用三种 Windows 内核对象协同工作：

1. **命名互斥体 (Mutex)** — 同版本检测
   - 名称：`YunJiCode_SingleInstance_v{VERSION}`
   - 每个版本有独立的互斥体，不同版本互不影响

2. **命名共享内存 (FileMapping)** — 存储当前运行实例的 EXE 路径
   - 名称：`YunJiCode_Path_v{VERSION}`
   - 大小：1024 字节（UTF-16-LE 编码路径）

3. **命名事件 (Event)** — 优雅退出信号
   - 名称：`YunJiCode_ShutdownEvent`（跨版本共享）
   - 新版本/新路径实例设置此事件，旧版本定时器检测后优雅退出

### 修改注意事项

- **不要用 `psutil` 暴力 kill 进程** — 使用命名事件通知旧实例优雅退出
- **不要用文件锁或端口检测** — 命名互斥体是 Windows 上最可靠的单实例方案
- **窗口标题必须包含版本号** — `FindWindowW` 依赖窗口标题查找
- **共享内存路径比较大小写不敏感** — Windows 文件路径不区分大小写

## 常见问题

### Q: EXE 启动报 "DLL load failed while importing QtWebEngineWidgets"
A: 这是旧版 PyQt6 方案的问题：
1. **PyQt6 版本不匹配** — 检查 `pip show PyQt6 PyQt6-WebEngine`，确保版本一致
2. **使用了 `--onefile` 模式** — QtWebEngine 不支持 `--onefile`，必须使用 `--onedir`

### Q: 新版 pywebview 方案能用 onefile 吗？
A: **可以！** pywebview 调用系统 WebView2，没有 DLL 路径问题，`--onefile` 单文件 ~38MB。

### Q: launcher_stub 自删除会影响启动速度吗？
A: **不会。** `--cleanup=` 和 `cmd /c del` 都是非阻塞的 `subprocess.Popen`，launcher_stub 启动主程序后立即退出，删除操作在后台进行。

### Q: 自部署启动器体积多大？
A: ~15MB。只包含 Tkinter（进度条）+ urllib（下载），不含 PyQt6/pywebview/FastAPI 等大型依赖。

### Q: 前端页面空白
A: 检查 `desktop/dist/index.html` 或 `static/index.html` 是否存在。如果不存在，先构建前端。

### Q: 软件更新提示 "不是 Git 仓库"
A: EXE 需要放在 Git 仓库目录下运行。确保 `dev/` 目录有 `.git/`，且 EXE 在 `dev/` 或 `dev/ver/` 下。

### Q: git pull 更新后 .env 被覆盖
A: 更新流程使用 `git stash` 保护本地修改（如 .env），更新后 `git stash pop` 恢复。
