# Windows 桌面应用单实例控制机制 — 技术研究案例

> 项目：云集智能编程工作站  
> 日期：2026-05-12  
> 技术栈：Python / PyQt6 / Windows API (ctypes)

---

## 一、问题背景

桌面应用通常需要确保同一程序不会重复启动多个实例，但实际场景比"禁止重复启动"更复杂：

| 场景 | 期望行为 |
|------|----------|
| 用户双击正在运行的同一个 EXE | 不应再启动一个，而是**激活已有窗口** |
| 新版本 EXE 替代旧版本 | 旧版本应**优雅退出**，非暴力终止 |
| 同版本但不同路径的 EXE | 新启旧退，不应两个同时运行 |

粗暴的"检测进程名 → kill"方案存在严重问题：可能误杀同名进程、丢失未保存数据、资源未正确释放。

## 二、方案演进

### ❌ 方案一：psutil 检测进程名 + kill

```python
# 早期方案（已废弃）
import psutil
for proc in psutil.process_iter():
    if proc.name() == "云集智能编程工作站.exe":
        proc.kill()  # 暴力终止，不安全
```

**问题**：
- 暴力终止，不触发 `closeEvent`，资源无法释放
- 可能误杀不同版本的同名进程
- 无法区分"同一个 EXE"还是"不同路径的同名 EXE"
- kill 后端口/文件锁可能未释放

### ❌ 方案二：端口监听检测

```python
import socket
def is_already_running(port=12345):
    s = socket.socket()
    try:
        s.bind(("127.0.0.1", port))
        return False
    except OSError:
        return True  # 端口被占，说明已有实例
```

**问题**：
- 端口可能被其他程序占用（假阳性）
- 防火墙可能拦截
- 无法区分版本
- 无法激活已有窗口
- 端口残留问题（进程崩溃后端口未释放）

### ✅ 方案三：Windows 命名内核对象（当前方案）

使用三种 Windows 内核对象协同工作：

1. **命名互斥体 (Mutex)** — 同版本检测
2. **命名共享内存 (FileMapping)** — 存储当前实例的 EXE 路径
3. **命名事件 (Event)** — 跨版本优雅退出信号

**优势**：
- 内核对象随进程生命周期自动清理（进程崩溃也不会残留）
- 命名空间隔离，不与端口/文件系统冲突
- 精确区分"同版本同路径" vs "同版本不同路径" vs "不同版本"
- 支持优雅退出（非暴力终止）

## 三、技术架构

### 3.1 整体流程

```
新实例启动
    │
    ├─ 创建版本互斥体 "YunJiCode_SingleInstance_v{VERSION}"
    │
    ├─ 互斥体创建成功？（GetLastError != ERROR_ALREADY_EXISTS）
    │   │
    │   ├─ YES → 本版本无其他实例运行
    │   │         │
    │   │         ├─ 设置全局 Shutdown Event（通知所有旧版本退出）
    │   │         ├─ 等待 0.3s（旧版本退出时间）
    │   │         ├─ 重置 Shutdown Event
    │   │         └─ 将自身 EXE 路径写入共享内存
    │   │
    │   └─ NO → 同版本已有实例运行
    │             │
    │             ├─ 读取共享内存中的 EXE 路径
    │             │
    │             ├─ 路径与自身相同？
    │             │   │
    │             │   ├─ YES → 激活已运行窗口 → 退出
    │             │   │
    │             │   └─ NO → 设置 Shutdown Event → 等待旧实例退出
    │             │            → 重新创建互斥体 → 继续启动
    │             │
    │             └─ （如果旧实例迟迟未退出 → 提示用户稍后重试）
```

### 3.2 三种内核对象详解

#### 对象一：命名互斥体 (Mutex)

```python
MUTEX_NAME = f"YunJiCode_SingleInstance_v{VERSION}"
_instance_mutex = _kernel32.CreateMutexW(None, True, MUTEX_NAME)
if ctypes.GetLastError() == ERROR_ALREADY_EXISTS:
    # 同版本已有实例
```

**设计要点**：
- 互斥体名称包含版本号，不同版本互不影响
- `CreateMutexW` 在互斥体已存在时返回有效句柄，但 `GetLastError` 返回 `ERROR_ALREADY_EXISTS (183)`
- 进程退出后互斥体自动释放（内核引用计数归零时销毁）
- 即使进程崩溃，互斥体也会被操作系统回收，无残留问题

**为什么不用全局互斥体？**
如果所有版本共用一个互斥体，则新版本无法启动（因为旧版本已持有）。版本化互斥体让不同版本可以同时短暂存在，新版本有机会通知旧版本退出。

#### 对象二：命名共享内存 (FileMapping)

```python
PATH_MAPPING_NAME = f"YunJiCode_Path_v{VERSION}"
PATH_MAPPING_SIZE = 1024

# 写入路径
_path_mapping = _kernel32.CreateFileMappingW(
    -1, None, PAGE_READWRITE, 0, PATH_MAPPING_SIZE, PATH_MAPPING_NAME
)
ptr = _kernel32.MapViewOfFile(_path_mapping, FILE_MAP_ALL_ACCESS, 0, 0, PATH_MAPPING_SIZE)
ctypes.memmove(ptr, path_bytes, len(path_bytes))
_kernel32.UnmapViewOfFile(ptr)

# 读取路径
mapping = _kernel32.OpenFileMappingW(FILE_MAP_ALL_ACCESS, False, PATH_MAPPING_NAME)
ptr = _kernel32.MapViewOfFile(mapping, FILE_MAP_ALL_ACCESS, 0, 0, PATH_MAPPING_SIZE)
raw = ctypes.string_at(ptr, PATH_MAPPING_SIZE)
path = raw.decode("utf-16-le").rstrip("\x00")
```

**设计要点**：
- 使用 `CreateFileMappingW(-1, ...)` 创建页面文件支持的共享内存（不关联磁盘文件）
- 路径用 UTF-16-LE 编码（Windows 原生 Unicode 编码），支持中文路径
- 大小 1024 字节，远超 MAX_PATH (520 字节)
- 版本化命名，与互斥体版本一致，确保读取的是同版本实例的路径
- 共享内存随最后一个句柄关闭而销毁

**为什么需要共享内存？**

仅凭互斥体只能知道"同版本有实例在运行"，但无法区分是同一个 EXE 还是不同路径的 EXE。共享内存存储了运行中实例的 EXE 完整路径，新实例可以比较路径做出不同决策。

#### 对象三：命名事件 (Event)

```python
SHUTDOWN_EVENT_NAME = "YunJiCode_ShutdownEvent"  # 跨版本共享！

# 新实例发出退出信号
_shutdown_event = _kernel32.CreateEventW(None, True, False, SHUTDOWN_EVENT_NAME)
_kernel32.SetEvent(_shutdown_event)

# 旧实例检测退出信号（定时器每 500ms 调用）
def _is_shutdown_signaled() -> bool:
    return _kernel32.WaitForSingleObject(_shutdown_event, 0) == 0  # WAIT_OBJECT_0

# 新实例等待旧实例退出后重置事件
_kernel32.ResetEvent(_shutdown_event)
```

**设计要点**：
- 事件名称**不包含版本号**，跨版本共享，确保任何新版本都能通知旧版本退出
- 使用手动重置事件（`True`），一旦 `SetEvent`，所有等待者都能收到
- 新实例发出信号后短暂等待，然后 `ResetEvent`，确保自身不会被自己的信号误杀
- 旧实例通过 500ms 定时器轮询检测，发现信号后调用 `self.close()` 触发优雅退出

**为什么不用自动重置事件？**
自动重置事件只唤醒一个等待者。如果有多个旧版本同时运行，只有一个会收到信号。手动重置事件确保所有旧版本都能检测到退出信号。

## 四、关键实现细节

### 4.1 窗口激活（同路径场景）

```python
def _activate_running_instance():
    hwnd = _user32.FindWindowW(None, f"云集智能编程工作站 v{VERSION}")
    if hwnd:
        if _user32.IsIconic(hwnd):          # 如果最小化
            _user32.ShowWindow(hwnd, 9)      # SW_RESTORE
        _user32.SetForegroundWindow(hwnd)    # 前置显示
        return True
    return False
```

**注意事项**：
- `FindWindowW` 通过窗口标题查找，因此窗口标题必须包含版本号
- `SetForegroundWindow` 在 Windows 上有安全限制：只有前台进程或被前台进程启动的进程才能设置前台窗口。但同一 EXE 的进程通常可以成功
- 如果窗口最小化，必须先 `ShowWindow(SW_RESTORE)` 恢复，否则 `SetForegroundWindow` 可能无效

### 4.2 不同路径同版本的处理

```python
if ctypes.GetLastError() == ERROR_ALREADY_EXISTS:
    existing_path = _read_exe_path_from_shared_memory()
    my_path = sys.executable  # PyInstaller 打包后即为 EXE 路径
    same_path = existing_path and (existing_path.lower() == my_path.lower())

    if same_path:
        # 同一 EXE → 激活窗口
        _activate_running_instance()
        sys.exit(0)
    else:
        # 不同路径 → 通知旧实例退出，然后接管
        _shutdown_event = _kernel32.CreateEventW(None, True, False, SHUTDOWN_EVENT_NAME)
        _kernel32.SetEvent(_shutdown_event)
        time.sleep(0.5)  # 等待旧实例退出
        _kernel32.CloseHandle(_shutdown_event)
        # 重新创建互斥体
        _instance_mutex = _kernel32.CreateMutexW(None, True, MUTEX_NAME)
```

**路径比较**：
- Windows 文件路径不区分大小写，必须 `.lower()` 后比较
- `sys.executable` 在 PyInstaller 打包后返回 EXE 自身路径，开发模式下返回 Python 解释器路径

### 4.3 优雅退出的保证

```python
# MainWindow.__init__ 中
self._shutdown_timer = QTimer(self)
self._shutdown_timer.timeout.connect(self._check_shutdown_signal)
self._shutdown_timer.start(500)  # 每 500ms 检查

def _check_shutdown_signal(self):
    if _is_shutdown_signaled():
        print("[APP] 收到关闭信号，正在优雅退出...")
        self.close()  # 触发 closeEvent → 释放资源 → 退出

def closeEvent(self, event):
    _cleanup_single_instance()  # 释放互斥体、事件、共享内存
    event.accept()
```

**为什么用定时器而不是线程等待？**
- `WaitForSingleObject` 在主线程中会阻塞 UI
- QTimer 轮询开销极小（500ms 一次，系统调用耗时 <1μs）
- 500ms 的响应延迟在"版本升级"场景中完全可接受

### 4.4 资源清理

```python
def _cleanup_single_instance():
    global _instance_mutex, _shutdown_event, _path_mapping
    if _instance_mutex:
        _kernel32.ReleaseMutex(_instance_mutex)   # 先释放（所有权）
        _kernel32.CloseHandle(_instance_mutex)     # 再关闭句柄
        _instance_mutex = None
    if _shutdown_event:
        _kernel32.CloseHandle(_shutdown_event)
        _shutdown_event = None
    if _path_mapping:
        _kernel32.CloseHandle(_path_mapping)       # 共享内存句柄
        _path_mapping = None
```

**注意**：
- 互斥体必须先 `ReleaseMutex`（释放所有权）再 `CloseHandle`
- 共享内存只需关闭句柄，当所有句柄关闭后操作系统自动回收
- 事件只需关闭句柄

## 八、注意事项与踩坑记录

### 8.1 `sys.executable` 的行为差异

| 运行方式 | `sys.executable` 值 |
|----------|---------------------|
| PyInstaller `--onedir` 打包的 EXE | EXE 文件完整路径 ✅ |
| PyInstaller `--onefile` 打包的 EXE | 临时解压目录中的 Python 解释器 ❌ |
| `python main.py` 开发模式 | Python 解释器路径 ❌ |

> 在 `--onefile` 模式下，应使用 `sys.argv[0]` 或 `__file__` 替代。本项目使用 `--onedir`，无此问题。

### 8.2 共享内存的编码

Windows 路径可能包含中文（如 `E:\软件开发\...`），必须用 UTF-16-LE 编码：

```python
path_bytes = exe_path.encode("utf-16-le") + b"\x00\x00"  # 双零终止
```

读取时需要正确处理终止符：

```python
raw = ctypes.string_at(ptr, PATH_MAPPING_SIZE)
end = raw.find(b"\x00\x00")
if end > 0:
    raw = raw[:end + 2]
path = raw.decode("utf-16-le", errors="ignore").rstrip("\x00")
```

### 8.3 `SetForegroundWindow` 的安全限制

Windows 限制只有前台进程才能设置前台窗口。同一 EXE 启动的第二个进程通常可以成功，但如果被安全策略阻止，窗口会闪烁任务栏图标而非前置。可通过以下方式绕过（需谨慎使用）：

```python
# 允许 SetForegroundWindow（附加输入权限）
user32.AllowSetForegroundWindow(-1)  # ASFW_ANY
```

### 8.4 内核对象命名空间

在 Terminal Services / 远程桌面环境中，命名内核对象在**每个会话**中有独立命名空间。这意味着：

- 同一台机器上不同用户会话中的实例互不影响（默认行为）
- 如果需要跨会话检测，需使用 `Global\` 前缀：`Global\YunJiCode_SingleInstance_v{VERSION}`
- 使用 `Global\` 前缀需要 `SeCreateGlobalPrivilege` 权限（普通用户通常有）

本项目使用默认会话命名空间，不同用户会话中的实例互不干扰。
