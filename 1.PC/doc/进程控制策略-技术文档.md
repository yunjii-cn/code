## 1. 背景与目标

### 1.1 问题域

云集智能编程工作站是 PyQt6 + QWebEngineView 开发的桌面 IDE，启动慢、体积大、独占资源多。当用户重复点击 EXE 启动图标、或者开发模式下多次执行 `python main.py` 时，如果不做进程控制，会出现：

| 问题 | 后果 |
|------|------|
| 多个 PyQt6 实例同时启动 | 互相抢同一个 WebView2 user data dir → 渲染崩溃 |
| 多个端口占用同一个 Ollama / node 子进程 | 端口冲突，服务挂掉 |
| 多个进程写同一个 `data/projects.json` | 文件锁竞争、数据损坏 |
| 用户旧窗口没关闭就启动新版本 | 旧版本还在跑后台子进程，新版本以为资源空闲 |

### 1.2 设计目标

- ✅ **开发模式**（`python main.py`）：新进程杀掉旧 python main.py 进程，自己接管
- ✅ **EXE 模式**（`云集智能编程工作站.exe`）：新进程杀掉同名前缀的旧 EXE，自己接管
- ✅ **杀同名是最简单的杀进程方式**：直接按 EXE 文件名前缀（或 python main.py）匹配，命中即 `TerminateProcess`
- ✅ **Mutex 占位**：用于防两个进程同时启动时的 race condition
- ✅ **资源名固定不带版本号**：升级是切换版本（关旧开新），不存在同时运行
- ✅ **进程崩溃保护**：若旧实例已死，新实例无感知地接管

### 1.3 设计原则

- **简单 > 复杂**：用最少的代码实现单实例控制
- **杀 > 通知**：直接 `TerminateProcess` 比优雅通知（SetEvent + 等 0.3s）简单一个量级
- **无版本号**：MUTEX_NAME 固定字符串，跨升级都通用

## 2. 整体架构

### 2.1 单层控制模型

```
┌─────────────────────────────────────────────────────────────┐
│                  EXE/dev 启动入口                              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ launcher.py (EXE 入口) / python main.py (开发入口)    │   │
│  │  ┌────────────────────────────────────────────────┐  │   │
│  │  │ ① 防篡改校验 (EXE 模式，launcher.py 独占)       │  │   │
│  │  │ ② 冻结模式 stdout 抑制 (EXE 模式)              │  │   │
│  │  │ ③ import main → main()                          │  │   │
│  │  └────────────────────────────────────────────────┘  │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                  main.py 主入口 (统一单实例控制)              │
│  ┌──────────────────────────────────────────────────────┐   │
│  │ ① 自部署 (onefile 模式)                               │   │
│  │ ② _ensure_single_instance()                          │   │
│  │     - _kill_same_name_processes()  ← 杀同名前缀       │   │
│  │     - CreateMutexW 占位                              │   │
│  │ ③ QApplication 启动 → MainWindow                      │   │
│  │ ④ closeEvent → _cleanup_single_instance()            │   │
│  └──────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

**关键变化**（v2.0）：
- ❌ 删除 main.py 里的"共享内存 / SHUTDOWN_EVENT / 激活窗口"复杂方案
- ❌ 删除 launcher.py 里的"强杀旧进程"（与 main.py 重复）
- ✅ 统一在 main.py 入口处理单实例控制
- ✅ launcher.py 退化为纯 EXE 入口（防篡改 + stdout 抑制 + import main）

### 2.2 为什么用"杀同名"

| 方案 | 代码量 | 复杂度 | 体验 |
|------|:---:|:---:|------|
| ❌ 共享内存 + SetEvent + 激活窗口 | ~150 行 | 高 | 开新窗口时旧窗口被激活 |
| ❌ Mutex + 找窗口 + SetForegroundWindow | ~80 行 | 中 | 同上 |
| ✅ **杀同名 + Mutex 占位** | **~70 行** | **低** | **开新窗口即接管** |

用户场景：用户希望"再点一次图标就能用上最新版本"，不需要"激活旧窗口"这种反直觉的体验。

## 3. 开发模式进程管理

### 3.1 启动入口

```
启动命令: python main.py
入口: main.py 的 main() 函数
单实例控制: _ensure_single_instance() 在 main() 第一步执行
```

### 3.2 杀同名的判定逻辑

开发模式下，python.exe 是解释器，所有脚本都跑在 python.exe 进程里。需要根据**命令行参数**判断是不是同项目：

```python
if exe_name in ('python.exe', 'pythonw.exe'):
    cmdline = ' '.join(psutil.Process(pid).cmdline()).lower()
    # 匹配 cmdline 含 main.py（bat 启动时不含 1.pc 路径，放宽匹配）
    if 'main.py' in cmdline:
        should_kill = True
```

**匹配规则**：
- ✅ `python E:\...\1.PC\app\main.py` → 杀
- ✅ `python E:\...\main.py`（无 1.pc 路径，bat 启动场景）→ 杀
- ❌ `python E:\...\1.PC\app\tests\test_main.py` → 不杀（不含 `main.py` 字符串）
- ❌ `python -c "import main"` → 不杀（cmdline 是 `-c` 参数，不含 `main.py`）

> 关键安全措施：**跳过自己 + 自己祖先链上的所有进程**。在 Windows 上 PowerShell/IDE 启动时，subprocess 会派生出 conhost/cmd 包装层（PID 跟 main.py 不同，但 cmdline 可能含 main.py），杀错会导致自己被连带结束。

### 3.3 杀进程后等待

```python
if pids_to_kill:
    for _ in range(20):  # 最多 2 秒
        time.sleep(0.1)
        # 检查所有 pid 是否已退出（exit_code != STILL_ACTIVE=259）
        if not still_alive:
            break
```

为什么等待：
- `TerminateProcess` 是**异步**的，调用后立即返回
- 必须等旧进程真正退出，否则 mutex 占位会冲突
- 2 秒上限：极端情况兜底，避免卡死

## 4. EXE 模式：杀同名 + Mutex 占位

### 4.1 启动入口

```
启动命令: 云集智能编程工作站.exe (PyInstaller --onefile 打包)
入口: launcher.py → main() → import main → main() → _ensure_single_instance()
```

### 4.2 杀同名的判定逻辑

EXE 模式下，按 **EXE 文件名前缀**匹配：

```python
base_prefix = "云集智能编程工作站".lower()  # "云集智能编程工作站"
should_kill = (
    exe_name.startswith(base_prefix)
    and exe_name.endswith('.exe')
)
```

**匹配规则**：
- ✅ `云集智能编程工作站.exe` → 杀
- ✅ `云集智能编程工作站-v2026.06.16.1430.exe`（旧版本残留）→ 杀
- ✅ `云集智能编程工作站`（无后缀）→ 不杀（endswith('.exe') 失败）
- ❌ `python.exe` → 不杀
- ❌ `其他应用.exe` → 不杀

### 4.3 升级场景

```
时序:
  1. 用户运行旧版: 云集智能编程工作站-v2026.06.16.exe (PID=100)
  2. 用户运行新版: 云集智能编程工作站-v2026.06.17.exe (PID=200)
  3. 新版 _ensure_single_instance() 触发
  4. 枚举进程 → 命中"云集智能编程工作站-v2026.06.16.exe" (PID=100)
  5. TerminateProcess(PID=100) → 旧版进程被杀
  6. 等旧版退出 (≤2s)
  7. 新版 CreateMutexW → 占位成功
  8. 新版启动主窗口
```

旧版的所有资源（WebView2 user data、Ollama 子进程、文件锁）随旧版进程被系统强制释放，新版无需关心清理。

## 5. 核心数据结构

### 5.1 全局资源

| 资源 | 名称 | 类型 | 用途 |
|------|------|------|------|
| MUTEX | `YunJiCode_SingleInstance` | 命名互斥体 | 防止两个进程同时初始化（race 兜底） |
| 进程列表 | 实时枚举 | Toolhelp32Snapshot | 杀同名前缀的旧 EXE / 旧 python main.py |

### 5.2 为什么不用共享内存 / SHUTDOWN_EVENT

**v1.0 方案**（已废弃）：
- 共享内存：旧实例写自己的 EXE 路径 → 新实例读出来判断是否同路径
- SHUTDOWN_EVENT：新实例 SetEvent → 旧实例轮询检测 → 优雅退出

**v2.0 简化**：
- 杀同名后，旧实例直接 `TerminateProcess`，没有"优雅退出"概念
- 不需要传递路径（杀的是所有同名前缀的 EXE）
- 不需要事件通知（杀进程本身就是通知）

### 5.3 为什么 Mutex 名不带版本号

```python
MUTEX_NAME = "YunJiCode_SingleInstance"  # 固定字符串
```

**v1.0 错误思路**：
```python
# ❌ 错误：MUTEX_NAME = f"YunJiCode_SingleInstance_v{VERSION}"
# 问题：
#   1. 跨升级时旧版 v1 的 mutex 还存在，新版 v2 启动时 CreateMutexW 不会冲突
#   2. 多个版本残留导致 mutex 残留
#   3. 开发模式下 VERSION 不稳定（datetime.now()），mutex 跨分钟失效
```

**v2.0 正确做法**：
- 升级是"关旧开新"（杀完旧 EXE 再启新 EXE），不存在同时跑
- mutex 残留不影响：旧 EXE 杀完后 mutex 句柄随进程释放
- 固定名 = 简单 = 不会失效

## 6. 关键代码解析

### 6.1 `_kill_same_name_processes()` — 杀同名

```python
def _kill_same_name_processes():
    """杀掉所有同名旧进程（EXE 模式按 BRAND_NAME 前缀，开发模式按 python main.py）"""
    if sys.platform != 'win32':
        return

    my_pid = _kernel32.GetCurrentProcessId()
    is_frozen = getattr(sys, 'frozen', False)
    base_prefix = BRAND_NAME.lower()

    # 1. 创建进程快照
    snap = _kernel32.CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0)
    if snap == INVALID_HANDLE_VALUE:
        return

    # 2. 收集当前进程的祖先链（防止杀掉自己的父/祖父导致自己被连带）
    my_ancestor_pids = set()
    try:
        import psutil as _ps_anc
        cur = _ps_anc.Process(my_pid)
        while True:
            par = cur.parent()
            if par is None or par.pid == 0:
                break
            my_ancestor_pids.add(par.pid)
            cur = par
    except Exception:
        pass

    # 3. 遍历进程，找同名
    entry = PROCESSENTRY32W()
    entry.dwSize = ctypes.sizeof(PROCESSENTRY32W)
    pids_to_kill = []

    if _kernel32.Process32FirstW(snap, ctypes.byref(entry)):
        while True:
            pid = entry.th32ProcessID
            if pid != my_pid and pid not in my_ancestor_pids:
                exe_name = (entry.szExeFile or "").lower()
                should_kill = False
                if is_frozen:
                    should_kill = exe_name.startswith(base_prefix) and exe_name.endswith('.exe')
                else:
                    if exe_name in ('python.exe', 'pythonw.exe'):
                        try:
                            import psutil
                            cmdline = ' '.join(psutil.Process(pid).cmdline()).lower()
                            if 'main.py' in cmdline:
                                should_kill = True
                        except Exception:
                            pass
                if should_kill:
                    pids_to_kill.append(pid)

            entry.dwSize = ctypes.sizeof(PROCESSENTRY32W)
            if not _kernel32.Process32NextW(snap, ctypes.byref(entry)):
                break

    _kernel32.CloseHandle(snap)

    # 3. 杀进程（TerminateProcess）
    PROCESS_TERMINATE = 0x0001
    for pid in pids_to_kill:
        h = _kernel32.OpenProcess(PROCESS_TERMINATE, False, pid)
        if h:
            _kernel32.TerminateProcess(h, 0)
            _kernel32.CloseHandle(h)

    # 4. 等旧进程退出（≤2 秒）
    if pids_to_kill:
        for _ in range(20):
            time.sleep(0.1)
            still_alive = []
            for pid in pids_to_kill:
                h = _kernel32.OpenProcess(0x00100000, False, pid)
                if h:
                    exit_code = ctypes.c_ulong()
                    if _kernel32.GetExitCodeProcess(h, ctypes.byref(exit_code)) and exit_code.value == 259:
                        still_alive.append(pid)
                    _kernel32.CloseHandle(h)
            if not still_alive:
                break
```

### 6.2 `_ensure_single_instance()` — 入口函数

```python
def _ensure_single_instance():
    """单实例控制: 杀同名进程 → mutex 占位（防 race）"""
    global _instance_mutex
    if sys.platform != 'win32':
        return

    # 1. 杀所有同名旧进程
    _kill_same_name_processes()

    # 2. 创建 mutex 占位
    _instance_mutex = _kernel32.CreateMutexW(None, True, MUTEX_NAME)
    if ctypes.GetLastError() == ERROR_ALREADY_EXISTS:
        # 兜底: race 时再杀一次
        _kernel32.CloseHandle(_instance_mutex)
        _instance_mutex = None
        _kill_same_name_processes()
        _instance_mutex = _kernel32.CreateMutexW(None, True, MUTEX_NAME)
        if ctypes.GetLastError() == ERROR_ALREADY_EXISTS:
            _kernel32.CloseHandle(_instance_mutex)
            _instance_mutex = None
            ctypes.windll.user32.MessageBoxW(
                0, f"{BRAND_NAME} 旧实例未能退出，请手动结束进程后重试。", "提示", 0x40
            )
            sys.exit(0)
```

**为什么需要 mutex 兜底**：
- 进程 A、B 同时启动
- A 杀 B、B 杀 A → 都成功
- A 杀完 B 后 B 也杀了 A → A 死、B 死
- 但 A 还没退出时 A 创建 mutex → B 杀 A 后也尝试创建 mutex → B 失败
- 这时 mutex 兜底"再杀一次"就能处理

实际上这种 race 极难触发（两个进程要在毫秒级同时启动），但兜底逻辑让代码更稳健。

### 6.3 `_cleanup_single_instance()` — 退出清理

```python
def _cleanup_single_instance():
    """清理单实例资源（窗口关闭时调用）"""
    global _instance_mutex
    if _instance_mutex:
        _kernel32.ReleaseMutex(_instance_mutex)
        _kernel32.CloseHandle(_instance_mutex)
        _instance_mutex = None
```

调用时机：
- `MainWindow.closeEvent` → `_cleanup_single_instance()`
- 自部署分支 → `_cleanup_single_instance()`

## 8. 异常处理与边界情况

### 8.1 旧实例卡死

- `TerminateProcess` 是**强制**的，无论目标进程是否响应都能杀
- 操作系统会清理目标进程的所有资源（文件锁、共享内存、子进程）
- 2 秒等待上限：极端情况（系统卡顿）兜底

### 8.2 psutil 不可用（开发模式）

```python
try:
    import psutil
    cmdline = ' '.join(psutil.Process(pid).cmdline()).lower()
    ...
except Exception:
    pass  # psutil 缺失时跳过该 pid（不会误杀）
```

### 8.3 Toolhelp32Snapshot 失败

```python
snap = _kernel32.CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0)
if snap == INVALID_HANDLE_VALUE:
    return  # 快照失败 → 跳过杀进程 → 继续走 mutex（可能冲突）
```

### 8.4 Mutex 已存在但旧进程已死

如果旧进程在 TerminateProcess 之后、CreateMutexW 之前被杀（理论上不会发生，因为等待循环会确认 pid 已退出），mutex 可能因为旧进程句柄未释放而残留：
- 实际不会发生：mutex 句柄随进程死亡自动释放
- 兜底：mutex 创建失败时，再杀一次 + 再创建

### 8.5 跨平台（Linux / macOS）

```python
if sys.platform != 'win32':
    return  # Linux/macOS 跳过单实例控制
```

后续可扩展 `fcntl.flock`（Linux）或 `flock` 实现非 Windows 平台的单实例控制。
